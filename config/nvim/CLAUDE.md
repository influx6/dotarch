# Neovim config conventions

LazyVim-based config. The entrypoint is `init.lua` → `require("alex.core")` +
`require("alex.lazy")`. **`config/lazy.lua` is the old entrypoint** (commented
out in `init.lua`) — do not edit it.

## Layout

- `lua/alex/lazy.lua` — lazy.nvim setup. Imports `lazyvim.plugins` (LazyVim
  base), `alex.plugins`, and `alex.plugins.lsp`.
- `lua/alex/core/` — non-plugin config: `options`, `keymaps`, `autocmds`,
  `logsearch`.
- `lua/alex/plugins/` — plugin specs. `import = "alex.plugins"` is a **directory
  import**: lazy loads `init.lua` *and* every `plugin-*.lua` sibling *and* any
  subdirectory with its own `init.lua` (`lsp/`, `after/`). A plugin file is not
  wired up anywhere else — it just needs to live in this directory.
- `lua/alex/plugins/lsp/` — LSP-related specs (`lspconfig`, `mason`, `blink`).

## Adding / changing a plugin

- One plugin (or cohesive group) per `lua/alex/plugins/plugin-<name>.lua`,
  returning a lazy.nvim spec table.
- Prefer `opts = { … }` (lazy deep-merges with the plugin's defaults). Use
  `config = function(_, opts) … end` only when you need imperative setup — e.g.
  wiring a `Snacks.toggle(...)` keymap (`plugin-snacks.lua`,
  `plugin-markdown.lua`).
- Lazy-load deliberately (`ft`, `keys`, `event`, `cmd`) rather than loading
  everything at startup.

## Docs

- `docs/` = reference material (plugin option dumps, language setups like
  `haskell.md`, `markdown.md`).
- `docs/guides/` = task how-tos. Action-first, with a TL;DR table, and they link
  the config file with a relative path (e.g.
  `../../lua/alex/core/logsearch.lua`).
- New guide → add a line to `docs/guides/README.md`. New language/feature doc →
  add a link under "Language & feature docs" in `config/nvim/README.md`.

## Notes

- `lazy-lock.json` is generated by lazy.nvim (`:Lazy sync`). Commit its changes
  alongside plugin changes; don't hand-edit it.
- Markdown rendering is `plugin-markdown.lua` (render-markdown.nvim), lazy-loaded
  on markdown filetypes, toggled with `<leader>um`.
